# Где мы остановились

Остановка по команде владельца 28 июля 2026, ~18:00 МСК. Все агенты остановлены.
Старт пилота — **31 июля**, в запасе двое суток.

---

## Коротко

Платформа переписана с демо-уровня на прод-архитектуру и функционально готова к
пилоту. Не сделано главное: **ничего не проверено на живой инфраструктуре** —
на машине разработки нет Docker и не поднимается PostgreSQL.

15 коммитов, 159 тестов зелёные, 10 честно пропущены до живой базы.

## Что НЕ проверено — читать перед выкатом

Ни один пункт ниже не является «наверное работает». Это то, что физически
невозможно было проверить на этой машине.

1. **Миграции на живом PostgreSQL.** Схема компилируется в корректный SQL офлайн,
   но `alembic upgrade head` на настоящей базе не запускался ни разу.
2. **Сборка Docker-образов и запуск compose.** Синтаксис валиден, образы запинены
   по digest, но `docker build` не выполнялся.
3. **Работа GPU-ноды.** Обёртка GigaAM написана по реальному коду модели с
   HuggingFace, HTTP-логика покрыта 10 тестами, но модель ни разу не грузилась.
4. **Вёрстка глазами.** Экран входа я успел открыть в браузере на десктопной
   ширине — список сотрудников рисуется правильно. На 360px посмотреть не успел.
5. **Живой микрофон и гарнитура.** Кнопка на проводной гарнитуре ловится через
   mediaSession — это решение из документации, на железе не проверялось.
6. **Redis.** Тесты авторизации идут на fakeredis.

### Почему не проверено

На машине нет Docker. Встроенный PostgreSQL не поднимается: `initdb` падает с
`FATAL: invalid byte sequence for encoding "UTF8": 0xc2 0xeb` — это «Вл» в CP1251,
Postgres читает имя аккаунта Windows, а оно кириллическое. Ни ASCII-путь для
данных, ни `--locale=C` не помогают. Это тупик, а не недоработка.

**Решение согласовано с владельцем:** проверка идёт через GitHub Actions —
в `.github/workflows/ci.yml` уже прописаны настоящие PostgreSQL 16 и Redis,
прогон миграций и сборка образа.

## Первое, что делать при продолжении

1. **Установить gh и залить репозиторий** (ждёт действия владельца):
   ```
   winget install --id GitHub.cli -e --silent
   gh auth login
   gh repo create onvy --private --source=. --push
   ```
   CI прогонит миграции на живом Postgres и соберёт образ. Это снимает пункты 1 и 2
   из списка непроверенного.
2. **Развернуть VPS** по `docs/runbook-deploy.md`, накатить миграции, поднять compose.
3. **Завести точку**: `scripts/seed_venue.py` — создаёт чайхану, группы связи,
   сотрудников с PIN и кличками, печатает список для раздачи. См.
   `docs/runbook-pilot-setup.md`.
4. **Залить меню** из CSV через кабинет управляющего, обязательно сначала с превью.
5. **Прогнать вживую**: два телефона, гарнитуры, реальный вопрос по меню и реплика
   на кухню. Замерить, укладываемся ли в 2.5 секунды.

## Решения, которые лучше не пересматривать без причины

- **Voice-ID запрещён.** Как только продукт начнёт опознавать человека по голосу,
  он попадает под режим биометрических ПДн и ГИС ЕБС: аккредитация Минцифры,
  штрафы за утечку до сотен миллионов. Транскрибация и перевод под этот режим
  не попадают. Это ограничение архитектурное, а не временное.
- **Аллергены без данных — «уточните на кухне».** Ассистент не имеет права
  угадывать: информация о составе и аллергенах по закону на заведении. В карточке
  пустое поле и подтверждённое «аллергенов нет» — разные значения на уровне колонки.
- **GigaAM-v3 не подходит**, она русскоязычная. Нужна ветка `GigaAM-Multilingual`
  (ru, en, kk, ky, uz). Таджикского нет ни в одной — он уходит в облако.
- **Метрика пилота — до/после на одной группе**, не A/B внутри точки: контроль
  в одном зале загрязняется, а выборки 5–15 человек не хватает для значимости.
  Первые 3–5 смен исключаются как эффект новизны.

## Незакрытые вопросы

1. **Дата и объём пилота уточнены** (31 июля), но число сотрудников и языки
   конкретной чайханы так и не подтверждены разговором с управляющим.
2. **Таджикское распознавание** нужно проверить руками: официального подтверждения
   поддержки у Яндекса найти не удалось.
3. **Правовой пакет** (§7 спеки) — согласия сотрудников, допсоглашения, табличка
   в зале. Без него включать устройства нельзя, а он не начат.
4. **Личный кабинет сотрудника** с целями в схеме не реализован — договорились
   свести к статистике за смену, полноценные цели после пилота. Экрана пока нет.
5. ~~Никнеймы доделаны не полностью~~ — **закрыто 28 июля.** Уникальность клички
   в точке гарантирована частичным индексом, проверка при заведении точки
   отклоняет короткие, многословные, совпадающие с отделом, блюдом или другой
   кличкой смены. Кличка попала в распечатку, правила выбора — в runbook.
6. Две миграции вместо одной начальной (никнеймы отдельным файлом). Работает,
   ни одна нигде не применялась — при желании можно схлопнуть.
