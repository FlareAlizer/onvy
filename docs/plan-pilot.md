## 4. Чего НЕ делаем — чтобы не тратить две недели впустую

- **GPU-нода и своя модель.** Облако укладывается в полторы секунды при бюджете 2.5.
  Аренда карты — 45–52 тысячи в месяц против сотен рублей на сотрудника. К своей
  модели возвращаемся, когда точек станет много, а не на первом пилоте.
- **Интеграция с iiko / R-Keeper.** Вне пилота (§11). Меню грузится файлом, порт для
  будущей интеграции уже заложен.
- **Геймификация, баллы, обучающие курсы.** Вне пилота (§11). Экраны скрыть.
- **Нативные приложения.** Веб на телефоне работает, микрофон требует HTTPS — он есть.
- **Voice-ID и определение говорящего.** Правовой периметр. Никогда, ни в каком виде.
- **Рефакторинг консоли.** Она перенесена как есть и работает. Трогать её глубже,
  чем подключение к API, — это неделя, которой у нас нет.

## 5. Работа вдвоём в одном репозитории

Репозиторий приватный на бесплатном тарифе, поэтому **защиту веток GitHub включить
нельзя** — это платная функция. Значит правила держатся на договорённости:

- Ветка на задачу, вливание через pull request, даже если ревьюер один.
- **CI обязателен**: шесть проверок (ruff, tsc, pytest на настоящем Postgres, сборка
  фронтенда, аудит зависимостей, публикация образа). Красный CI не вливаем.
- Не пушить в `master` напрямую. Технически это возможно — договорённость и есть
  единственная защита.
- Выкат делает один человек и говорит об этом второму: `scripts/deploy-pull.sh` на
  сервере тянет образ из реестра.
- Секреты не коммитим. `.env` в gitignore, токены — только на сервере.

## 6. Как понять, что готовы

Пилот можно включать, когда одновременно верно:

1. Двое коллег в разных углах зала слышат друг друга через рацию, включая перевод.
2. Управляющий слышит смену, не держа открытым экран рации.
3. Кнопка на гарнитуре работает на тех телефонах, которые будут в смене.
4. В базе настоящее меню чайханы, аллергены подтверждены кухней.
5. Бэкап снимается по расписанию и проверено восстановление.
6. Ни один экран не показывает выдуманные цифры.
7. Правовой пакет подписан.
8. Baseline по POS собирается уже две недели.
9. **Боевой сервер поднят на актуальном образе** — CI собирает образ на каждый
   пуш в `master`, но сервер его не подтягивает сам. Проверять перед каждой
   сменой: `docker inspect onvy-api-1 --format '{{.Image}}'` на сервере против
   `docker manifest inspect ghcr.io/flarealizer/onvy/api:latest` (или просто
   `bash scripts/deploy-pull.sh`, если сомневаетесь).
