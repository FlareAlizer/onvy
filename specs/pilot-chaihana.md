# Спека: пилот Onvy в чайхане

Статус: **черновик L0** — разделы, помеченные `⏳`, заполняются по результатам исследований
(агенты `asr-research`, `horeca-research`).
Источник продукта: `Onvy_ Realtime Voice Assistant for Russian Frontline Re.pdf`.
Обновлено: 2026-07-28.

---

## 1. Цель

Платный пилот в одной чайхане, по итогам которого есть **измеренные цифры** для
инвестраунда: Δ среднего чека и/или Δ скорости обслуживания в пилотной группе против
контрольной, подтверждённая себестоимость on-premise ASR, LTV/CAC на реальных данных.

Планка кода: **пилот = прод в миниатюре**. Никаких «потом перепишем»: тот же стек,
та же схема данных, тот же деплой, что поедут на второго и десятого клиента.
Единственное, что масштабируется потом — количество нод, не архитектура.

## 2. Зафиксированные решения

| Решение | Выбор | Следствие |
|---|---|---|
| Устройство сотрудника | Личный телефон + проводная гарнитура с кнопкой | PWA в браузере, HTTPS обязателен (иначе нет микрофона), никакой закупки железа |
| ASR | Сразу on-premise на арендованной GPU-ноде в РФ | Себестоимость доказывается на пилоте; латентность под контролем |
| Модель ASR | GigaAM (Сбер) — покрытие языков ⏳ проверяется | При нехватке языков — карта «язык → провайдер» в конфиге |
| Сервер приложения | VPS в РФ (Selectel / Timeweb / reg.ru) | Данные в РФ (152-ФЗ), Docker compose + Caddy TLS |
| Источник меню | Ручной ввод + импорт Excel/CSV | Домен строится через `MenuSourcePort`; адаптер iiko/R-Keeper — после пилота, без ломки домена |
| Ревью кода | Человек (владелец продукта) | Мелкие лупы, каждый — читаемый дифф; агенты не мержат сами |
| Языки | ru + узб/тадж/кирг/каз/азер/туркм + en | Мультиязычность — ядро ценности, а не опция |

## 3. Роли и группы

| Роль | Что делает голосом | Кабинет |
|---|---|---|
| Официант | Спрашивает ассистента про блюдо/стоп-лист, говорит на кухню и в бар | Личный: цели, прогресс |
| Кухня | Принимает и подтверждает реплики зала | Нет (только связь) |
| Бар | То же по напиткам | Нет (только связь) |
| Хостес | Broadcast по залу | Нет |
| Управляющий | Слышит всё, ведёт стоп-лист | Полный: стоп-лист, персонал, аналитика, метрики пилота |

Группы связи: `зал`, `кухня`, `бар`, `все`. Маршрутизация голосом: «Онви, скажи кухне…».

## 4. Сценарии и приёмка

### S1. Подсказка по меню
Официант жмёт кнопку → «Онви, что в составе лагмана» → в ухе ответ голосом на его языке.
**Приёмка:** ответ строится только по данным меню заведения (не выдумка модели);
если блюдо в стоп-листе — ассистент говорит об этом первым; p95 от отпускания кнопки
до начала звука ≤ 2.5 с; ответ на языке профиля сотрудника.

### S2. Связь с переводом
Официант-узбек говорит на узбекском «два лагмана без острого» → повар-таджик слышит
на таджикском; ответ повара приходит официанту на узбекском.
**Приёмка:** доставка ≤ 2 с p95; при отказе перевода доставляется оригинал с явной
пометкой (никогда не тишина); реплика хранится на языке оригинала + перевод.

### S3. Стоп-лист
Управляющий с телефона выключает позицию → следующий запрос официанта уже знает.
**Приёмка:** ≤ 5 секунд действий управляющего; изменение видно всем ≤ 3 с; ведётся история.

### S4. Broadcast
«Онви, скажи всем: гости на 12-й стол» → слышат все онлайн в группе.
**Приёмка:** доставка только своей точке и своей группе; отправитель слышит подтверждение.

### S5. Кабинет управляющего
Кто на смене, история реплик, метрики пилота, латентность стека.
**Приёмка:** метрики выгружаются в CSV для отчёта инвестору.

## 5. Нефункциональные требования

- **Латентность.** Бюджет S1: запись ≤ 0.3 с + ASR ≤ 0.8 с + поиск/LLM ≤ 0.8 с + TTS ≤ 0.6 с.
  Каждая стадия меряется отдельно и пишется в лог — цифра в отчёт пилота.
- **Доступность.** Падение GPU-ноды не роняет связь между сотрудниками: рация продолжает
  работать (деградация до «без перевода»), ассистент отвечает «сейчас недоступен».
- **Безопасность.** Логин по PIN, JWT (короткий access + refresh), роли, WS по одноразовому
  тикету, rate-limit. Сотрудник слышит только свою точку и свою группу.
- **Данные.** Всё в РФ. Аудио хранится ⏳ (срок и режим — по итогам правового ресёрча),
  доступ к записям — только управляющий и владелец.
- **Сеть.** Wi-Fi заведения нестабилен: клиент переживает обрыв WS и переподключается
  сам, реплики не теряются.
- **Эргономика.** Кнопка PTT нажимается одной рукой не глядя; экран читается при
  ярком свете и под углом; проверка на 360 px обязательна.

## 6. Архитектура (порты и адаптеры)

```
transport (HTTP/WS)  →  application (сценарии)  →  domain  →  infrastructure (адаптеры)
```

Порты, за которые всё цепляется:

| Порт | Адаптер на пилоте | Потом |
|---|---|---|
| `SpeechRecognitionPort` | GigaAM на GPU-ноде | + облачный фолбэк по языкам |
| `SpeechSynthesisPort` | ⏳ по итогам ресёрча | локальный TTS |
| `TranslationPort` | ⏳ | локальный NLLB на той же карте |
| `AnswerPort` (LLM над меню) | YandexGPT / локальная модель | своя |
| `MenuSourcePort` | ручной ввод + Excel-импорт | iiko / R-Keeper |
| `EventBusPort` | Redis pub/sub | он же |

Правило: домен не знает ни одного имени вендора. Смена провайдера = новый файл в
`infrastructure/`, ноль правок в домене. Для тестов у каждого порта есть fake-адаптер.

## 7. Данные

Postgres + Alembic с первого дня (никакого `create_all`). Основные сущности:
`venue` (точка), `employee` (роль, язык, PIN-хеш), `group`, `menu_item`
(состав, аллергены, острота, время отдачи, вес, цена), `stop_list_entry`,
`utterance` (реплика: оригинал + перевод + метрики стадий), `assistant_query`,
`metric_snapshot`. Мультиточечность заложена сразу — `venue_id` во всех запросах.

## 8. Метрики пилота ⏳

Заполняется по итогам `horeca-research`: что реально снимается с POS, как строить
контрольную группу внутри одной точки, какие ловушки.

## 9. Не входит в пилот

Геймификация сверх базовых целей, обучающие курсы, индор-локация, интеграции с POS,
голосовые рассылки HQ, мобильные нативные приложения, биллинг и тарифы, свои гарнитуры.

## 10. Открытые вопросы

1. **Дата старта пилота** — ждём от владельца; под неё режется состав.
2. Языковое покрытие GigaAM ⏳ — определяет, нужен ли второй ASR-провайдер.
3. Правовой чеклист по голосу сотрудников ⏳ — может стать блокером до включения.
4. Что за учётная система в этой чайхане (iiko / R-Keeper / тетрадь) — влияет на приоритет адаптера.
5. Есть ли у заведения нормальный Wi-Fi в зале и на кухне — влияет на режим деградации.
